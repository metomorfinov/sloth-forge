# Agent Orchestrator: Управление и распределение задач

Данный скилл определяет строгий протокол работы с несколькими агентами для предотвращения перерасхода лимитов и хаотичных правок.

## 1. Лимиты и правила вызова сабагентов
- **Максимум 1–2 сабагента одновременно**: Никогда не запускай параллельно 4–5 агентов. Модель Opus расходует большой объем контекста; параллельные агенты быстро сожгут дневные лимиты.
- **Изолированная зона ответственности**: Каждый сабагент получает ОДНУ конкретную задачу (например, только аудит фронтенда ИЛИ только оптимизация Vulkan-шейдера).
- **Сворачивание контекста**: Как только сабагент завершил работу и вернул результат, его сессия закрывается. Все выводы фиксируются в центральном плане.

## 2. Протокол декомпозиции (/batch)
1. **Анализ зависимостей**: Разбей задачу на последовательные фазы:
   - Фаза 1: Сбор фактов и аудит (чтение файлов, поиск ошибок без изменений).
   - Фаза 2: Точечные изменения бэкенда (API, типы, логика).
   - Фаза 3: Точечные изменения фронтенда (компоненты, стили).
   - Фаза 4: Верификация и тесты.
2. **Принцип малых шагов**: Не изменяй более 2–3 файлов за одну итерацию batch.
3. **Объяснение на русском**: Перед каждым batch-шагом объясни 1–2 простыми предложениями суть действия.

## 3. Фиксация памяти (Memory MCP)
- Сохраняй ключевые архитектурные решения и пути к важным модулям через MCP `memory`.
- При начале новой сессии сверяйся с сохраненным графом проекта.
